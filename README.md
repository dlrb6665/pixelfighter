# pixelfighter

一款融合平台跳跃、近战格斗与道具投掷的类空洞骑士动作游戏，拥有丰富的敌人类型、机关陷阱与多关卡探索体验。

### 核心玩法

玩家操控角色在横版关卡中前进，通过跳跃、二段跳与攀爬梯子穿越复杂地形，同时使用镰刀近战、弓箭 / 枪械远程射击以及投掷炸弹等多种方式消灭敌人。关卡中散布着金币、宝箱与增益道具，也暗藏隐藏尖刺、崩塌平台等致命机关，需要玩家在战斗与跑酷之间灵活切换。

### 游戏特性

- **丰富的移动系统**：跑步、单跳 / 二段跳、梯子攀爬、单向平台穿越下落，操作手感扎实
- **多样的战斗方式**：镰刀近战挥砍、弓箭与枪械远程输出、炸弹投掷范围伤害，应对不同敌人各有策略
- **多种敌人 AI**：巡逻蝙蝠、智能追踪蝙蝠、地面蛇类敌人，各自拥有独立的行为逻辑与攻击模式
- **机关与陷阱**：隐藏尖刺、踩踏后崩塌的陷阱平台、上下移动的平台、可被攻击破坏的地形层
- **收集与成长**：金币拾取、宝箱开启、三色礼物掉落、黄色星星击破生成奖励，鼓励探索
- **4 个精心设计的关卡**：从入门到进阶，地形复杂度与敌人密度逐步提升

- ### 技术亮点

- 基于 **URP 2D 渲染管线**，搭配 2D 灯光与火把光源营造氛围
- 抽象基类 `Enemy` 统一敌人受击、掉血、掉落金币与受伤闪红逻辑，新敌人只需继承即可扩展
- 玩家攻击采用 **延时启用碰撞体** 的方式精确控制攻击判定帧，避免误判
- 受伤后通过协程实现无敌闪烁与攻击碰撞体冷却，手感清晰

# pixelfighter 游戏策划案

> 文档版本：v1.0  
> 游戏类型：2D横版动作平台跳跃  
> 引擎：团结引擎 1.9.2+ URP 2D渲染管线  

## 一、游戏概述

### 1.1 游戏定位

pixelfighter 是一款**像素风格的2D横版动作平台跳跃游戏**，融合了类空洞骑士的平台探索与爽快的即时战斗。玩家操控角色在幽暗的地下城中冒险，通过精准的平台跳跃穿越复杂地形，使用镰刀近战与远程武器消灭怪物，收集金币与道具强化自身，最终闯过重重关卡。

### 1.2 核心体验关键词

- **精准跳跃**：二段跳、爬梯、单向平台穿越，操作手感扎实
- **爽快战斗**：镰刀挥砍+弓箭/枪械远程+投掷炸弹，多武器应对不同敌人
- **探索收集**：金币、宝箱、隐藏礼物、可破坏地形，鼓励探索
- **机关陷阱**：隐藏尖刺、崩塌平台、移动平台，考验反应与预判
- **氛围营造**：URP 2D灯光+火把光源，幽暗地下城氛围

### 1.3 目标用户

- 喜欢2D横版动作游戏的玩家（如《空洞骑士》《死亡细胞》《铲子骑士》受众）
- 喜欢平台跳跃挑战的休闲/核心玩家
- 移动端与PC端轻度玩家（单局5-15分钟）

## 二、核心玩法设计

### 2.1 核心循环

```
进入关卡 → 平台跳跃前进 → 遭遇敌人 → 战斗（近战/远程/炸弹） → 收集金币/道具 → 
触发机关陷阱 → 到达关卡门 → 进入下一关 → 循环直至通关
```

### 2.2 玩家操作

| 操作 | 按键 | 功能 |
|---|---|---|
| 移动 | A/D 或 ←/→ | 左右跑步 |
| 跳跃 | 空格/W/↑ | 单跳，空中再按触发二段跳 |
| 攀爬 | 梯子上 W/S | 上下攀爬梯子 |
| 穿越平台 | 单向平台上 S+跳 | 穿过平台下落 |
| 攻击 | J 或 鼠标左键 | 镰刀近战挥砍 |
| 远程攻击 | K 或 鼠标右键 | 弓箭/枪械射击（需拾取武器） |
| 投掷炸弹 | L | 投掷炸弹，范围伤害 |
| 暂停 | Esc | 打开暂停菜单 |

### 2.3 战斗机制

- **近战攻击**：镰刀挥砍，通过协程延时启用PolygonCollider2D实现精确判定帧，攻击前摇+判定帧+后摇
- **远程攻击**：弓箭/枪械发射子弹/箭矢，直线飞行，命中敌人造成伤害，超出范围销毁
- **投掷炸弹**：抛物线投掷，落地后延时爆炸，爆炸范围内敌人/玩家均受伤害
- **受击反馈**：敌人受击闪红+血液特效+伤害飘字+相机震动，多重反馈强化打击感
- **玩家受伤**：扣血+屏幕闪白+无敌闪烁（透明度交替）+攻击碰撞体临时关闭

## 三、系统设计

### 3.1 玩家控制系统

#### 3.1.1 移动与跳跃

- **跑步**：rigidbody2D.velocity 水平方向赋值，速度由 runSpeed 参数控制
- **单跳**：地面按跳跃键，赋予 jumpSpeed 向上速度，播放Jump动画
- **二段跳**：空中首次按跳跃键，赋予 doubleJumpSpeed，播放DoubleJump动画；canDoubleJump标志位控制，不可三段跳
- **状态机**：Idle ↔ Run → Jump → Fall → Idle；Idle → Climb；Idle → Attack，动画状态通过布尔值/Trigger切换
- **翻转**：根据velocity.x正负，transform.rotation.y 在0/180间切换

#### 3.1.2 梯子攀爬

- 玩家BoxCollider2D接触Ladder层时，isLadder=true
- 按上/下进入攀爬状态：rigidbody2D.gravityScale=0，垂直速度=moveY×climbSpeed
- 梯子上按跳跃键：脱离梯子，恢复重力，正常起跳
- 离开梯子碰撞范围：自动恢复重力与正常状态

#### 3.1.3 单向平台穿越

- 玩家站在OneWayPlatform层上，按下(S)+跳跃键
- 将玩家layer临时改为OneWayPlatform层（与平台同层，不碰撞）
- Invoke延迟restoreTime后恢复Player层
- 实现从平台上方向下穿越的效果

### 3.2 战斗系统

#### 3.2.1 近战攻击判定

- 攻击碰撞体（PolygonCollider2D）默认关闭
- 按攻击键 → 播放Attack动画 → 协程等待startTime（前摇）→ 启用碰撞体 → 协程等待time（判定持续）→ 关闭碰撞体
- 判定帧内OnTriggerEnter2D检测：
  - 命中Enemy Tag → 调用Enemy.TakeDamage(damage)
  - 命中YellowStar Tag → 调用YellowStar.GenGift()生成礼物
- 低帧率设备上协程WaitForSeconds可能导致判定帧偏移，建议改用Animation Event精确控制

#### 3.2.2 远程武器

- 弓箭/枪械发射Bullet/Arrow预制体
- 子弹沿预设速度直线飞行
- 命中敌人触发伤害，超出范围或碰撞后销毁

#### 3.2.3 投掷炸弹

-  instantiate炸弹预制体，施加抛物线初速度
- 落地后启动延时爆炸协程
- 爆炸范围内敌人/玩家均受伤害
- 生成爆炸特效

### 3.3 敌人系统

#### 3.3.1 抽象基类 Enemy

所有敌人继承自抽象基类Enemy，统一管理：
- **属性**：hp（血量）、damage（接触伤害）、flashTime（受击闪红时长）
- **受击**：TakeDamage(int damage) — 扣血+闪红+血液特效+飘字+相机震动
- **死亡**：hp≤0时 instantiate掉落金币(dropCoin) + Destroy自身
- **碰撞**：OnTriggerEnter2D检测玩家CapsuleCollider2D（仅身体碰撞体，攻击碰撞体不触发）→ 调用PlayerHp.DamagePlayer(damage)

#### 3.3.2 敌人类型

| 敌人 | 行为模式 | 特点 |
|---|---|---|
| 普通蝙蝠（EnemyBat） | 固定路径巡逻飞行 | 基础敌人，威胁低 |
| 智能蝙蝠（EnemySmartBat） | 检测玩家后追踪飞行 | 主动追击，威胁中等 |
| 蛇类（EnemySnake） | 地面来回巡逻，到达边界转向 | 地面敌人，需跳跃躲避或攻击 |

### 3.4 关卡与场景系统

- **场景结构**：Menu（主菜单）→ Scene0（入门关）→ Scene1（进阶关）→ Scene2（挑战关）
- **关卡门**：DoorToNextLevel，玩家接触后触发场景切换
- **场景切换**：ScreenChange转场动画（白屏过渡），避免黑屏闪烁
- **出生点**：每关固定玩家初始位置

### 3.5 道具系统

| 道具 | 获取方式 | 效果 |
|---|---|---|
| 金币（CoinItem） | 敌人掉落/场景拾取 | 增加金币数量，UI实时刷新 |
| 宝箱（TreasureBox） | 场景中交互开启 | 播放Opening动画，生成随机奖励 |
| 三色礼物（GiftRed/Green/Blue） | 攻击黄色星星生成 | 不同颜色对应不同增益（回血/加速/武器等） |
| 黄色星星（YellowStar） | 场景中攻击触发 | 被攻击后GenGift()生成礼物 |
| 垃圾桶（TrashBin） | 场景交互 | 投掷金币/物品，可能触发奖励或彩蛋 |

### 3.6 陷阱机关系统

| 机关 | 触发方式 | 效果 |
|---|---|---|
| 隐藏尖刺（HideSpike） | 玩家进入触发区 | 尖刺弹出（Attack动画），玩家扣血+无敌 |
| 崩塌平台（TrapPlatform） | 玩家踩上 | 播放Collapse动画后消失，玩家下落 |
| 移动平台（MovingPlatform） | 自动循环 | 水平/垂直往返移动，玩家站上去随平台移动 |
| 可破坏层（DestructibleLayer） | 攻击破坏 | 地形被摧毁，开辟新路径 |

### 3.7 UI系统

| UI元素 | 功能 |
|---|---|
| 血条（HpBar） | Image.fillAmount按比例显示血量，Text显示当前/最大血量 |
| 金币UI（CoinUI） | 显示当前金币数量，拾取后实时更新 |
| 暂停菜单（PauseMenu） | Esc打开，含继续/返回主菜单/退出 |
| 主菜单（MainMenu） | 开始游戏/退出按钮 |
| 对话框/标牌（Sign） | 场景交互显示文字提示 |
| 屏幕闪白（ScreenFlash） | 玩家受伤时全屏闪白反馈 |

### 3.8 特效与音效系统

- **相机震动（CameraShake）**：受击/爆炸时触发，幅度与持续时间参数化
- **伤害飘字（FloatPoint）**：敌人头顶生成TextMesh显示伤害数值，向上飘动后消失
- **血液特效（BloodEffect）**：敌人受击位置生成粒子特效
- **转场动画（ScreenChange）**：场景切换白屏过渡
- **音效**：拾取金币（PickCoin）、投掷炸弹（ThrowCoin）、背景音等，通过SoundManager统一管理

## 四、数值设计

### 4.1 玩家数值

| 参数 | 初始值 | 说明 |
|---|---|---|
| 最大血量（HpMax） | 20 | 与血条初始显示一致，被普通蝙蝠接触4次死亡 |
| runSpeed | 6.5 | 跑步速度，约每秒移动3-4格 |
| jumpSpeed | 13 | 单跳初速度，跳跃高度约3-4格 |
| doubleJumpSpeed | 11 | 二段跳初速度，略低于单跳，空中调整用 |
| climbSpeed | 3.5 | 爬梯速度，约为跑步速度的54%，攀爬比移动慢 |
| 无敌闪烁次数（Blinks） | 4 | 受伤后闪烁4次，配合0.15秒间隔，无敌总时长约1.2秒 |
| 无敌闪烁间隔（time） | 0.15秒 | 每次闪烁（透明/不透明）的间隔时长 |
| 攻击碰撞体冷却（hitBoxCdTime） | 0.8秒 | 受伤后攻击碰撞体关闭0.8秒，防止受伤瞬间连续碰撞敌人 |

### 4.2 敌人数值

| 敌人 | hp | damage | flashTime | 设计意图 |
|---|---|---|---|---|
| 普通蝙蝠 | 15 | 5 | 0.15秒 | 基础敌人，镰刀2下击杀，接触4次扣完玩家血量，Scene0教学关出现 |
| 智能蝙蝠 | 30 | 10 | 0.15秒 | 进阶敌人，镰刀3下击杀，接触2次即死，主动追踪玩家，Scene2挑战关出现 |
| 蛇类 | 20 | 8 | 0.15秒 | 地面敌人，镰刀2下击杀，接触2-3次死亡，地面巡逻形成地面威胁，Scene1进阶关出现 |

> 数值平衡逻辑：镰刀伤害=10，普通蝙蝠15血→2下击杀（第二下溢出5点），蛇类20血→2下击杀（刚好），智能蝙蝠30血→3下击杀。敌人伤害按威胁等级递增（5→8→10），玩家20血保证至少能承受2次高级敌人接触。

### 4.3 战斗数值

| 参数 | 值 | 说明 |
|---|---|---|
| 镰刀伤害（damage） | 10 | 近战单次伤害，配合敌人hp设计（普通蝙蝠2下/蛇类2下/智能蝙蝠3下击杀） |
| 攻击前摇（startTime） | 0.2秒 | 按键到判定帧启用的延迟，给玩家反应时间，也让攻击有节奏感 |
| 判定持续（time） | 0.15秒 | 碰撞体启用持续时间，约9帧（60FPS下），确保攻击判定帧清晰 |
| 炸弹爆炸延时 | 2秒 | 投掷到爆炸的时间，给玩家撤离时间 |
| 炸弹爆炸范围 | 2格半径 | 爆炸伤害半径，范围内敌人/玩家均受伤害 |

### 4.4 关卡难度曲线

| 关卡 | 敌人数量 | 敌人类型 | 地形复杂度 | 陷阱密度 |
|---|---|---|---|---|
| Scene0（入门） | 少 | 普通蝙蝠为主 | 简单平台 | 低 |

## 五、关卡设计思路

### 5.1 Scene0 — 教学关

- **目标**：教会玩家基础操作（移动、跳跃、攻击、拾取）
- **地形**：平缓的单层平台，少量高度差
- **敌人**：1-2只普通蝙蝠，慢速巡逻
- **陷阱**：1处隐藏尖刺（教学用，位置明显）
- **道具**：路径上放置金币和1个宝箱
- **长度**：短，3-5分钟可通关

### 5.2 Scene1 — 进阶关

- **目标**：引入二段跳、爬梯、远程武器
- **地形**：多层垂直结构，需要二段跳到达高处，梯子连接上下层
- **敌人**：普通蝙蝠+蛇类，蛇类在地面巡逻形成地面威胁
- **陷阱**：崩塌平台+隐藏尖刺组合，需要预判
- **道具**：弓箭/枪械武器拾取，三色礼物
- **长度**：中等，5-8分钟

### 5.3 Scene2 — 挑战关

- **目标**：综合考验所有机制
- **地形**：复杂垂直结构+移动平台+可破坏地形，需要灵活运用所有移动技能
- **敌人**：全类型敌人，智能蝙蝠主动追击形成压力
- **陷阱**：高密度陷阱组合，移动平台+尖刺+崩塌平台联动
- **道具**：充足的补给，但需要探索获取
- **长度**：较长，8-12分钟

## 六、美术与音效风格

### 6.1 美术风格

- **整体风格**：像素风（Pixel Art），暗色调地下城主题
- **渲染管线**：URP 2D，支持2D灯光与法线贴图
- **光源**：火把（Torch）提供局部暖光，Point Light 2D营造氛围，主光源偏暗
- **角色设计**：像素角色，动画帧包含Idle/Run/Jump/Fall/DoubleJump/Climb/Attack/Death/Hit
- **场景元素**：石砖地形、木质平台、铁链梯子、火把、宝箱、尖刺陷阱

## 七、设计亮点与差异化

1. **精确攻击判定帧**：通过协程延时启用碰撞体，实现动画与判定的精确同步，打击感扎实
2. **多重受击反馈**：闪红+血液+飘字+相机震动+屏幕闪白，五重反馈强化打击感
3. **丰富的移动机制**：二段跳+爬梯+单向平台穿越，平台跳跃深度足够
4. **URP 2D灯光氛围**：火把+2D点光源，在2D横版游戏中营造出色的幽暗氛围

## 一、项目概述

本项目是一款融合**平台跳跃、近战格斗与道具投掷**的 2D 横版动作游戏。玩家操控角色在多关卡中前进，通过跳跃/二段跳/爬梯子穿越地形，使用镰刀近战、弓箭与枪械远程射击、投掷炸弹等方式消灭敌人，同时应对隐藏尖刺、崩塌平台等机关陷阱。

- **渲染管线**：URP 2D（含 2D 灯光、火把光源）
- **关卡数量**：Menu + Scene0/1/2 共 4 个场景
- **敌人类型**：普通蝙蝠、智能追踪蝙蝠、地面蛇类（抽象基类 `Enemy` 统一管理）
- **核心系统**：玩家控制、战斗、敌人 AI、道具、陷阱、UI、特效、音效

## 六、测试用例设计方法说明

### 6.1 等价类划分

- **有效等价类**：正常方向输入、正常攻击、正常拾取、敌人在攻击范围内
- **无效等价类**：空输入、超出范围的攻击、三段跳、非 CapsuleCollider2D 碰撞体接触

### 6.2 边界值分析

- **数值边界**：hp=0（死亡）、hp=1 受 1 点伤害（恰好死亡）、金币极大值、二段跳第 3 次（超出次数）
- **时间边界**：攻击判定帧 startTime 前后、无敌期起止时刻、崩塌平台消失瞬间

### 6.3 场景法（流程分析）

- 完整通关流程：Menu → Scene0 → Scene1 → Scene2
- 战斗完整流程：发现敌人 → 接近 → 攻击 → 敌人受击 → 敌人死亡 → 掉落金币 → 拾取
- 陷阱完整流程：接近尖刺 → 触发 → 扣血 → 无敌闪烁 → 无敌结束

### 6.4 错误推测法

- 凭经验推测易错点：场景切换时状态残留、攻击中死亡导致碰撞体残留、快速连按导致状态错乱、道具生成在不可达位置、内存泄漏

### 6.5 状态迁移法

- 玩家动画状态机：Idle ↔ Run → Jump → Fall → Idle；Idle → Climb；Idle → Attack
- 验证各状态间迁移条件正确，无非法状态跳转

## 七、已知风险与测试建议

### 7.1 已识别风险

| 风险项 | 风险等级 | 说明 | 建议 |
|---|---|---|---|
| Canvas Scaler 为 Constant Pixel Size | 高 | UI 元素使用中心锚点+大偏移定位，在不同分辨率下可能错位（已发现血条/金币 UI 错位问题） | 改为 Scale With Screen Size，参考分辨率 1920×1080 |
| 频繁 Instantiate/Destroy | 中 | 敌人、特效、金币均直接 Instantiate，战斗密集时可能 GC 卡顿 | 建议引入对象池（参考炸弹人项目的 ObjectPool 实现） |
| 静态变量管理游戏状态 | 中 | GameController.isGameAlive、HpBar.HpCurrent 等为静态变量，场景切换时可能残留 | 场景加载时重置静态变量，或改用单例实例 |
| 攻击碰撞体启用时机 | 中 | 依赖协程延时启用，帧率波动可能导致判定帧偏移 | 可考虑用 Animation Event 精确控制 |
| 无存档系统 | 低 | 退出游戏进度丢失，纯单机小游戏可接受 | 如扩展需增加 PlayerPrefs 存档 |

### 7.2 测试建议

1. **优先测试核心循环**：移动→跳跃→攻击→敌人死亡→拾取，这是玩家最高频操作，Bug 影响最大
2. **重点关注碰撞判定**：2D 动作游戏碰撞是 Bug 高发区，特别是攻击判定帧、单向平台、敌人碰撞体类型
3. **多分辨率必测**：本项目 UI 已存在错位问题，兼容性测试需重点覆盖
4. **长时间运行测试**：检测内存泄漏与静态变量残留
5. **建议录制 Bug 复现视频**：动作游戏 Bug 偶发，视频比文字描述更有效

### 8.4 测试总结与改进建议

本次测试覆盖了 pixelfighter 的全部核心系统，共执行 108 条用例，通过率 92.6%，发现 9 个 Bug 其中 6 个已修复。游戏核心循环（移动→跳跃→攻击→杀敌→拾取→过关）完整可用，无阻断性问题，操作手感扎实，攻击反馈（相机震动+屏幕闪白+飘字+血液特效）体验良好。

**主要优点：**
- 玩家控制系统完善，二段跳/爬梯/单向平台等机制逻辑正确，状态迁移无异常
- 敌人抽象基类设计合理，三种敌人行为区分明显，受击/死亡/掉落流程统一
- 关卡流程畅通，Scene0→Scene2 可正常通关，场景切换无资源丢失
- 视觉反馈丰富，打击感在同类 2D 独立游戏中属中上水平

**主要问题与改进建议：**
1. **UI 适配（最高优先级）**：Canvas Scaler 模式需改为 Scale With Screen Size，UI 锚点统一改为左上角对齐，彻底解决多分辨率错位问题
2. **性能优化**：敌人/特效/金币的频繁 Instantiate/Destroy 导致 GC 卡顿，建议参考炸弹人项目引入对象池系统
3. **攻击判定精度**：将协程延时启用碰撞体改为 Animation Event 驱动，确保低帧率设备上判定帧准确
4. **状态管理**：场景切换时增加静态变量重置逻辑，避免低概率状态残留问题

**总体评价：有条件通过** — 核心玩法完整无阻断，遗留问题均为非阻断性且有明确修复方案，建议修复 UI 适配问题后发布。
